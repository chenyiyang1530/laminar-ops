# Laminar Ops · 层流净化设备智能监测运维一体化平台

面向医院洁净区域（手术室、ICU、静配中心、CSSD、实验室等）层流净化设备的
**在线监测 + 全流程运维** 平台。平台分为 **运维后台端** 与 **医院前台端**，两端数据隔离、权限隔离。

> 本项目为全新独立工程（`laminar-ops`），与工作区内的 RuoYi 参考项目无代码依赖。
> 数据库：`laminar_ops`，演示数据全部为本项目自有脚本。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Java 17 · Spring Boot 3.3.5 · MyBatis-Plus 3.5.9 · MySQL 8 · Redis · JWT |
| 运维后台 | Vue 3 · Vue Router 4 · Pinia · Element Plus · ECharts · Rollup 构建 |
| 医院前台 | Vue 3（独立应用，规划中，复用同一后端 `/api/portal/**`） |
| 数据库 | `laminar_ops`（51 张表，含系统权限与全部业务域） |

## 已实现

### 第一里程碑：平台底座

- **认证与权限**：JWT 登录、登录日志、账号停用/院方绑定校验；`@Perm` 接口权限 + 菜单/按钮权限；角色数据范围（全部/区域/医院/本人）。
- **组织与字典**：公司部门、岗位、用户、角色、菜单树、字典类型/数据接口。
- **工作台仪表盘**：医院/设备在线率/告警/工单/合同/证书 KPI，7 天告警与工单趋势、设备类型分布、最新告警、合同到期、到期任务、医院在线情况。
- **客户档案-医院管理**：分页查询、新增/编辑/删除、区域与字典联动、院方账号数据隔离。
- **平台骨架**：动态菜单路由、路由守卫、侧边栏/面包屑/消息入口、统一错误提示、SPA 静态托管（`/app`）。
- **数据底座**：院区/洁净区域/对接人/合同/设备类型/设备台账/监测点位/告警/工单/巡检/保养/证书/备件/文档/知识库/预算/消息 等 30+ 业务表与演示数据。

### 第二里程碑：通用档案引擎 + 消息中心

- **元数据驱动 CRUD**：`CrudRegistry` 登记资源（表、字段、字典、选项、关联显示、权限前缀），一套 `GenericCrudService` 提供分页/详情/新增/修改/删除/下拉选项，自动做字段白名单、参数化 SQL、医院数据范围校验与审计字段填充。
- **18 个档案页面**：院区、科室、洁净区域、客户对接人、维保合同、设备类型、设备台账、监测点位、告警规则、工程师、技能、证书、备件、图纸文档、知识库、预算、巡检计划、保养计划，均支持查询、分页、表单校验、字典标签、关联下拉。
- **消息中心**：告警/工单/保养/证书/合同等站内消息，支持未读角标（顶部铃铛 60s 轮询）、按类型/已读筛选、单条已读、全部已读，并按用户/角色广播隔离。

### 第三里程碑：实时监测与告警中心

- **采集模拟**：`MonitorCollectTask` 每 30 秒采集 44 个在线点位（温度、湿度、压差、风速、粒子、氧气压力、真空度），随机游走 + 低概率越限，写 Redis 最新值并每 5 分钟落历史表；首次启动自动回填 24 小时历史，保证曲线可用。
- **实时监测页**：设备卡片按医院/院区/区域展示，在线状态灯、关键指标实时值、10 秒自动刷新；点击进入设备详情抽屉，查看点位实时值、告警范围与 24 小时趋势曲线。
- **告警引擎**：按点位告警上下限判定，同一设备点位未消缺期间合并刷新（持续时长累计），自动分级（压差/氧气/真空紧急，温度/粒子重要，其余一般），生成 `biz_alarm_log` 并推送消息中心；紧急告警联动设备运行状态为故障。
- **告警中心**：活动/未确认/已确认/处理中/已消缺分栏筛选，支持确认、开始处理、消缺（必填根本原因/措施）、忽略，以及完整处理时间线追溯；消缺后自动恢复设备运行状态。
- **接口**：`/api/monitor/overview`、`/equipment/{id}`、`/history`、`/collect`；`/api/alarm/page`、`/{id}`、`confirm|handle|close|ignore`。

### 第四里程碑：工单全流程闭环

- **7 状态机**：待受理(0) → 待派工(1) → 处理中(2) → 待验收(3) → 待回访(4) → 已完成(5)，旁支已取消(6)；每次流转写 `biz_workorder_log`。
- **动作**：受理、派工（选择工程师并给工程师发消息）、到场签到、完工（维修报告 + 停机时长）、验收（通过进入待回访 / 驳回退回处理中）、报价、回访（满意度 1-5 分）、取消（必填原因）。
- **SLA**：按故障等级自动设置（P0 2h / P1 8h / P2 24h）。
- **告警联动**：告警追溯抽屉「一键转工单」，按告警级别映射工单等级，回写告警 `workorder_id`。
- **视图**：工单管理（全量、状态分栏、医院/等级/关键字筛选）、我的工单（工程师仅看本人），详情抽屉含费用明细与流转时间线。
- **接口**：`/api/workorder/page|my|{id}`、`create`、`receive|dispatch|arrive|finish|accept|quote|callback|cancel`、`from-alarm/{alarmId}`。

### 第五里程碑：巡检与预防性保养

- **周期生成**：`BizTaskScheduler` 每日 00:10（并在启动时）按计划 `next_run_date` 生成巡检/保养任务，自动写检查项（巡检取计划 JSON 模板，保养按内容拆分），并按日/周/月/季/年推进下次日期；`plan_time < 今天` 的未执行任务自动标记逾期。
- **执行闭环**：开始执行 → 逐项填写结果/实测值/备注 → 整体结果（正常/异常）→ 巡检异常必填问题描述 → 一键转维修工单（回写任务 `workorder_id` 与工单 `inspection_task_id/maintenance_task_id`）。
- **保养记录**：必填保养记录，可登记使用备件，异常同样可转工单。
- **数据范围**：院方账号仅见本院任务；工程师按 `assignee_id` 或未分配任务收敛。
- **页面**：巡检任务、保养任务支持待执行/逾期/执行中/已完成分栏、医院与编号筛选、手动生成到期任务、执行弹窗与查看模式。
- **接口**：`/api/inspection/task/*`、`/api/inspection/generate`；`/api/maintenance/task/*`、`/api/maintenance/generate`。

### 第六里程碑：系统管理与审计（后端）

- **用户管理**：分页/详情/新增/编辑/删除、重置密码（默认 123456）、启停用、角色分配（`sys_user_role`），排除院方账号。
- **角色权限**：角色列表/新增/编辑/删除、菜单树读取、角色菜单批量授权（`sys_role_menu`）、数据范围（all/region/hospital/self）。
- **组织与字典**：部门树查询/新增/编辑/删除（禁止删除有下级部门）；岗位、字典类型/数据复用通用 CRUD 资源，接口已就绪。
- **日志审计**：登录日志查询；新增 `OperLogInterceptor`，自动记录所有非 GET 业务写操作（操作人、URL、IP、结果、耗时），可按关键字分页查询。
- **定时任务**：`sys_job` 列表与启停，内置监测采集、巡检生成、保养生成三条任务记录。
- **系统监控**：在线用户（Redis `online:*`，登录写入、30 分钟过期、登出清除）、服务监控（JVM/OS/内存/运行时长）、缓存监控（Redis INFO）、数据监控（表行数与容量）。
- **接口**：`/api/system/user/*`、`/role/*`、`/dept/*`、`/log/login|oper`、`/job/*`、`/monitor/online|server|cache|data`。

### 第七里程碑：医院前台端（独立应用）

- 独立 Vue 3 应用 `web-admin/src-portal`，构建产物 `dist-portal`，由后端托管在 `/portal/**`，路由前缀 `/portal/`。
- 页面：**本院概览**（设备数/在线率/未处理告警/待办工单、最新告警、合同到期）、**设备监测**（本院设备卡片 + 15s 刷新 + 点位详情）、**设备告警**（活动/全部/已消缺 + 处理时间线）、**报修工单**（提交报修、进度跟踪、验收通过/驳回、流转记录）、**消息通知**（已读/全部已读）。
- 认证复用 JWT：登录后校验 `userType=2`，非院方账号拒绝；院方档案从 `biz_hospital_user` 解析本院。
- **数据隔离**：`/api/portal/**` 由拦截器强制院方身份；所有查询按 `hospital_id` 收敛；跨院访问设备/告警/工单统一返回 403；后台账号访问院方接口同样 403。
- 接口：`/api/portal/profile|dashboard|monitor|equipment-options|alarms|workorders|messages`。

### 第八里程碑：到期提醒、智能派单与报表

- **到期提醒**：`ReminderTask` 每日 09:00（启动时也执行）刷新证书/合同状态，并按剩余天数生成幂等消息（`biz_key` 去重）：合同提醒维保经理/区域主管，证书提醒工程师本人及维保经理；证书 60 天、合同按 `warn_days`（默认 90 天）。
- **智能派单**：`/api/dispatch/recommend/{workorderId}` 综合评分——服务该医院 +40、技能/专业匹配设备类型 +30、同区域 +10、在岗 +10、负载分（在手工单越少越高）、证书过期扣分，返回候选人、得分与推荐理由；页面可一键派工（复用工单派工接口）。
- **统计报表**：`/api/report/summary?year=` 返回合同金额、工单/告警总数、预算执行明细与执行率、月度工单量、费用构成、工单状态分布；前端报表页含 KPI、预算进度条、月度柱状图。
- **实测**：合同提醒 3 条、证书提醒 1 条；待派工工单 4 推荐出 3 名候选人（最高 105 分，理由含服务医院/技能匹配/同区域/在岗/负载）；报表返回 6 条预算、合同金额 284 万、工单 13 张。

## 前后端分离运行方式（开发）

后端只提供 `/api`，两个前端各自用 Vite 独立运行，通过代理访问后端：

```bash
# 1) 后端（任选其一）
#    IDEA 运行 LaminarOpsApplication，或：
cd backend && mvn spring-boot:run      # http://127.0.0.1:8080

# 2) 运维后台（Vite，5173）
cd web-admin
npm install
npm run dev                            # http://localhost:5173/login

# 3) 医院前台（Vite，5174）
npm run dev:portal                     # http://localhost:5174/login
```

- Vite 已配置代理：`/api`、`/upload` → `http://127.0.0.1:8080`，前端代码无需写死后端地址；
- 开发时前端地址是 **5173 / 5174**，不要再访问 8080 的 `/app`、`/portal`（那是生产托管模式）；
- 一键启动三个进程：右键运行 `start-dev.ps1`。

### 生产部署（可选两种）

1. **前后端分离部署**：前端构建为静态文件，交给 Nginx 托管，Nginx 把 `/api` 反代到后端。

   ```powershell
   # 构建到站点根路径（Windows PowerShell）
   cd web-admin
   $env:APP_BASE='/'; npm run build; npm run build:portal
   ```

   Nginx 示例：

   ```nginx
   server {
     listen 80;
     root D:/deploy/laminar-ops/dist;          # 运维后台
     location / { try_files $uri $uri/ /index.html; }
     location /api/ { proxy_pass http://127.0.0.1:8080/api/; }
     location /upload/ { proxy_pass http://127.0.0.1:8080/upload/; }

     location /portal/ {                        # 院方端
       alias D:/deploy/laminar-ops/dist-portal/;
       try_files $uri $uri/ /portal/index.html;
     }
   }
   ```

2. **后端托管**（默认，简单演示）：`npm run build` 产出 `/app` 基址，`npm run build:portal` 产出 `/portal` 基址，直接由 Spring Boot 托管。

Windows 服务器还建议按 [Redis8 部署与开机自启](docs/redis8-deployment.md) 安装 Redis8 服务、后端开机任务，并配置 Redis 内存/慢查询告警。

## 快速启动

### 1. 初始化数据库

```bash
mysql -uroot -p123456 -e "DROP DATABASE IF EXISTS laminar_ops;"
for f in sql/01_schema.sql sql/02_seed_core.sql sql/03_seed_demo.sql \
         sql/04_seed_ops.sql sql/04b_seed_workorder.sql sql/05_menu.sql; do
  mysql -uroot -p123456 --default-character-set=utf8mb4 < "$f"
done
```

### 2. 启动后端（8080）

```bash
cd backend
export JAVA_HOME=/path/to/jdk17
mvn -DskipTests package
java -jar target/laminar-ops-1.0.0.jar
```

配置见 `backend/src/main/resources/application.yml`（MySQL `root/123456`、Redis `127.0.0.1:6379`）。

### 3. 构建并访问前端

运维后台采用 Rollup 预构建，由后端在 `/app/**` 托管（同源，无跨域）：

```bash
cd web-admin
npm install          # 受限环境如遇 postinstall EPERM，可用 npm install --ignore-scripts
npm run build        # 产出 dist/，后端自动托管
```

访问：<http://127.0.0.1:8080/app/login>

### 第十四里程碑：数据范围与级联修复（第一批）

针对自查发现的越权与联动问题，完成以下修复：

- **统一数据范围**：新增 `DataScopeService`，按角色 `data_scope` 解析可见医院：
  - `all` 全部；`region` 本区域医院；`hospital` 本院；`self` 工程师服务医院；
  - 通用 CRUD、仪表盘、设备监测、告警、工单、巡检/保养均接入。
- **下拉级联**：`/api/crud/{res}/options` 支持 `hospitalId`、`campusId`、`departmentId` 参数并做范围过滤；
  前端 `CrudPage` 按「医院→院区→科室/洁净区→设备」级联加载，父级变化自动清空子级。
- **院方锁定**：院方账号的医院字段禁用并强制本院；创建/编辑时后端再次校验，跨院写入返回 403。
- **仪表盘隔离**：院方/区域/工程师的告警、合同、到期任务、医院分布、预算统计全部按可见医院过滤。
- **动作归属**：工单、巡检、保养的详情与操作校验“医院范围 + 本人负责”；派工校验工程师是否服务该医院。

### 第十六里程碑：第二批（监测与告警闭环）

- **编号唯一**：巡检/保养编号改为“当日最大序号 +1”，并加唯一索引；冲突自动跳过，避免删任务后重号。
- **告警规则接入**：优先匹配 `biz_alarm_rule`（设备级 → 设备类型级 → 全局），支持操作符、阈值、持续时长、级别、自动转工单；无匹配规则回退点位阈值。
- **自动恢复**：指标连续 3 个采集周期正常，系统自动消缺并恢复设备运行状态。
- **告警去重**：`active_point` 生成列 + 唯一索引，同一测点只保留一条活动告警；并发冲突自动合并。
- **离线检测**：新增每分钟任务，按心跳规则阈值标记离线并生成告警；恢复心跳/采集后自动关闭。
- **模拟数据治理**：模拟值按物理合理区间裁剪（风速/粒子/氧气不出现负值）；新增 `simulated` 标记，真实网关设备不再被模拟数据“保活”。
