> 版本：v1.0 ｜ 更新日期：2026-10-29 ｜ 适用工程：`D:\ideaWork\laminar-ops`

## 1. 平台概述

本平台面向医院洁净区域（手术室、ICU、静配中心、消毒供应中心、实验室等）的层流净化设备，提供「档案 → 监测 → 告警 → 工单 → 巡检/保养 → 结算/考核」的一体化运维能力。

平台分为两端：

| 端 | 使用者 | 职责 |
| --- | --- | --- |
| 运维后台 | 我方公司内部 | 客户档案、设备监测、告警处置、工单调度、巡检保养、人员资质、备件、预算、系统管理 |
| 医院前台 | 院方设备科/院感科/科室 | 查看本院设备与告警、提交报修、验收确认、接收消息 |

两端共用一套后端 API，但数据严格按医院隔离。

## 5. 运维后台操作

### 5.1 工作台

- KPI：联网医院、设备在线率、未处理/紧急告警、待办工单、本月工单、合同到期、证书到期；
- 图表：近 7 天告警与工单趋势、设备类型分布、医院在线情况；
- 列表：最新告警、合同到期提醒、到期巡检/保养任务。

### 5.2 客户档案

| 菜单 | 操作 |
| --- | --- |
| 医院管理 | 新增/编辑医院，维护等级、类型、性质、区域、联系人、经纬度 |
| 区域管理 | 维护业务区域（区域编码、负责人），医院新增时从这里选择所属区域 |
| 院区管理 | 按医院维护院区、地址、床位 |
| 科室管理 | 按院区维护科室、类型、负责人 |
| 洁净区域 | 维护区域类型、洁净级别、面积、设计温湿度/压差、院感要求 |
| 客户对接人 | 设备科/院感科/科室负责人等，标记主联系人 |
| 合同管理 | 合同编号、起止日期、金额、类型、负责人、预警天数 |

> 删除为物理删除，请先确认无关联设备/工单。

### 5.3 设备监测

| 菜单 | 操作 |
| --- | --- |
| 设备类型 | 层流机组、净化空调、新风、除湿、供氧汇流排、负压真空等 |
| 设备台账 | 绑定医院/院区/科室/洁净区域/设备类型，维护型号、协议、地址、运行状态 |
| 监测点位 | 每个设备维护温度/湿度/压差/风速/粒子/氧气/真空等点位及告警上下限 |
| 实时监测 | 设备卡片实时值（30 秒采集、10 秒刷新），点击设备查看点位与 24h 曲线 |
| 告警规则 | 配置指标、级别、比较符、阈值、持续时长、是否自动派单 |

**设备接入方式**

- 演示：后端内置采集任务，每 30 秒模拟生成数据；
- 真实网关：调用

```http
POST /api/open/monitor/report
Header: X-Monitor-Token: laminar-gateway
Content-Type: application/json

{"equipmentCode":"EQ-XM-0001","pointCode":"TEMP","value":23.5}
```

上报后自动写入 Redis 最新值、历史表，并触发告警判定。

### 5.4 告警中心

状态流转：

```
0 未确认 → 1 已确认 → 2 处理中 → 3 已消缺
                 ↘ 4 已忽略
```

| 操作 | 说明 |
| --- | --- |
| 确认 | 值班人员确认告警 |
| 处理 | 开始现场处理 |
| 消缺 | 必填根本原因与处理措施，记录消缺人与时间 |
| 忽略 | 填写原因（如传感器校准） |
| 追溯 | 查看完整处理时间线与操作人 |
| 转工单 | 一键生成维修工单，回写告警 `workorder_id` |

同一设备点位在未消缺期间自动合并，持续时长累计；紧急告警会将设备运行状态置为故障，消缺后恢复。

告警判定优先匹配告警规则（设备/类型/全局，支持阈值、操作符、持续时长、级别与自动转工单）；无匹配规则时回退点位阈值。指标连续 3 个采集周期恢复正常后自动消缺；设备心跳超时会生成离线告警。

### 5.5 工单管理

| 状态 | 含义 | 可用操作 |
| --- | --- | --- |
| 0 | 待受理 | 受理、取消 |
| 1 | 待派工 | 派工、取消 |
| 2 | 处理中 | 到场、完工、报价 |
| 3 | 待验收 | 验收通过/驳回、报价 |
| 4 | 待回访 | 回访 |
| 5 | 已完成 | 查看 |
| 6 | 已取消 | 查看 |

- **派工**：选择工程师后自动发送站内消息；SLA 按等级设置（P0 2h / P1 8h / P2 24h）。
- **验收**：通过进入待回访；驳回退回处理中。
- **报价**：处理中/待验收阶段提交金额与说明。
- **回访**：满意度 1–5 分，完成后关闭工单。
- **我的工单**：工程师只看本人派工单。

### 5.6 巡检任务

- 计划在「巡检计划」维护周期、执行人、检查项模板；
- 系统每日 00:10（启动时也执行）按 `next_run_date` 生成任务；
- 任务状态：0 待执行 / 1 执行中 / 2 已完成 / 3 已逾期 / 4 已取消；
- 执行时逐项填写结果、实测值、备注；整体异常可**转工单**；
- 逾期的待执行任务自动标记为已逾期。

### 5.7 保养任务

- 在「保养计划」维护设备、保养级别、周期、内容、执行人；
- 自动生成保养任务，执行时必填保养记录，可登记使用备件；
- 异常结果可转维修工单。

### 5.8 人员与资质

| 菜单 | 操作 |
| --- | --- |
| 工程师 | 维护姓名、电话、职称、专业、区域、在岗状态 |
| 技能标签 | 层流机组、净化空调、新风、除湿、供氧/负压、电气、检测等 |
| 资质证书 | 证书编号、发证机构、有效期、提醒天数，自动计算有效/即将到期/过期 |
| 智能派单 | 选择待派工工单，系统按医院/技能/区域/在岗/负载/证书评分推荐工程师，可一键派工 |

### 5.9 备件

- 备件台账：编码、名称、类别、规格、安全库存、当前库存、单价、库位；
- 领用流程：申请（多行备件）→ 批准/驳回 → 出库（校验库存、扣减、写流水）；
- 手工出入库：`POST /api/parts/stock`，写入库存流水。

### 5.10 文档与知识库

- 图纸文档：按分类、医院、设备归档，文件地址以 URL 形式保存；
- 知识库：故障案例、操作规程、应急预案、培训资料，支持富文本编辑（通用 CRUD 页面）。

> 当前版本未内置文件上传接口，文档/附件以 URL 方式维护，可后续扩展。

### 5.11 预算与报表

- 预算管理：按年度、医院/合同、科目编制预算；
- 执行登记：报表页预算明细行点击「登记执行」，录入金额/日期/备注，自动累加已执行金额并写流水；
- 统计报表：合同金额、工单/告警总数、预算执行率、月度工单、费用构成、工单状态分布。

### 5.12 消息中心

- 告警生成、工单派工、合同到期、证书到期等自动推送；
- 顶部铃铛显示未读数（60 秒轮询）；
- 支持按类型/已读筛选、单条已读、全部已读。

### 5.13 系统管理

| --- | --- |
| 用户管理 | 新增员工、分配部门/岗位/角色、重置密码、启停用 |
| 角色管理 | 角色 CRUD、数据范围、菜单树授权 |
| 部门管理 | 树形部门维护 |

## 7. 关键业务规则

| 规则 | 说明 |
| --- | --- |
| 告警分级 | 压差/氧气/真空 → 紧急；温度/粒子 → 重要；其余 → 一般 |
| 告警合并 | 同点位未消缺期间合并，刷新最近时间与持续时长 |
| SLA | P0 2h、P1 8h、P2 24h |
| 证书提醒 | 到期前 60 天提醒本人与维保经理，状态自动刷新 |
| 合同提醒 | 按 `warn_days`（默认 90 天）提醒维保经理/区域主管 |
| 预算预警 | 执行率 > 80% 黄色、> 100% 红色 |
| 数据隔离 | 院方按 `hospital_id`，区域主管按区域，工程师按本人 |

## 8. 定时任务

| 任务 | 频率 | 说明 |
| --- | --- | --- |
| 监测采集 | 30 秒 | 仅对 `simulated='1'` 的设备生成模拟数据并判定规则告警 |
| 设备离线检测 | 每分钟 | 心跳超时标记离线并生成离线告警，恢复心跳自动关闭 |
| 巡检任务生成 | 每日 00:10 | 按计划生成并标记逾期 |
| 保养任务生成 | 每日 00:20 | 按计划生成并标记逾期 |
| 合同/证书提醒 | 每日 09:00 | 刷新状态并推送消息 |

均可在「系统管理 → 定时任务」查看与启停。启停立即生效（由 `sys_job` 动态调度），每次执行后自动回写最近执行时间与结果。

> 院方消息中心接收本院告警、工单状态、合同到期提醒；科室用户仅接收本科室相关数据。

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 8080 被占用 | 结束旧 `java.exe`，或修改 `server.port` |
| 登录报 Redis 连接失败 | 启动 `D:\software\redis\redis-server.exe` |
| 页面 404 | 确认访问 `/app/login` 或 `/portal/login`；开发模式用 5173/5174 |
| Lombok 报“程序包不存在” | Maven Reload；确认 Module Dependencies 含 lombok；开启 Annotation Processing |
| 白屏 / 模块解析错误 | 强刷；确认没有直接打开 `web-admin/index.html`；开发模式必须访问 5173/5174 |
| 跨院 403 | 属正常数据隔离，用对应医院账号 |
| 前端 npm 安装失败 | 切换国内镜像或检查 Node 版本；`npm rebuild esbuild` |

## 11. 上线前建议

1. 修改 `laminar.jwt.secret`、数据库口令、设备网关 Token；
2. 关闭或替换模拟采集任务，接入真实网关；
3. 生产部署采用 Nginx 托管前端、反代 `/api` 与 `/upload`（配置示例见 `README.md`）；
4. 配置数据库备份、Redis 持久化、日志轮转；
5. 按院区/角色复核数据范围与账号权限；
6. 补充文件上传、电子签章、短信/邮件通知等扩展能力。
